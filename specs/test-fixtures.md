# Test fixtures

**Status:** In progress — export and daemon safeguards implemented; full plugin ownership remains blocked

**Surfaces:** Tests

## Contract

Live-test fixtures must identify their owned resources explicitly. Names, matching registration shapes, an empty earlier inventory, and successful process exit do not establish creation ownership or remote rollback. Test export queries use only captured fixture IDs and an explicit field allowlist, with a small declared row budget. They reject missing ownership, broadened schemas, unrelated results and over-budget results rather than silently truncating or adopting existing data. Related-record expansion and binary exports are not enabled for these account fixtures.

Plugin cleanup may remove only registrations whose creation by the current run is established and whose current IDs/relationships agree with that record. Preexisting registrations, including ones with expected names and shapes, are not adopted or cleaned. Uncertain submission, incomplete creation evidence, unexpected inventory or identity drift fails closed and retains safe recovery metadata. Cleanup must not expand to newly observed foreign registration IDs after a read/write race.

The current plugin preflight is only a partial implementation: it refuses populated preexisting registrations before entering the test body or teardown. An existing empty assembly is still permitted and may be updated by deployment. The existing deploy/list output does not supply creation receipts and exact registration identities; parent deletion can also cascade to a foreign child added after a client-side check. Full teardown ownership is therefore incomplete, and the ordinary cleanup path is not established safe for a live rerun.

CLI subprocess interruption reuses the existing shared bounded stop primitive and per-instance quarantine. The relevant daemon fixture must also bound asynchronous startup/shutdown/disposal paths, drain or safely handle stderr, preserve primary failures, and avoid secret-bearing arguments/output in diagnostics. Unconfirmed termination retains owned local evidence rather than pretending cleanup is safe. A confirmed parent exit is not a descendant or remote-operation rollback guarantee. Synchronous OS/filesystem work is not claimed to have a hard real-time deadline.
