## Highlights

PPDS adds safer workflows for editing Dataverse forms from an AI assistant, working in notebooks connected to different environments, and explicitly activating solution cloud flows.

- **MCP form authoring:** inspect forms and their stable section IDs, preview adding an existing column to an existing Main-form section, save and verify the unpublished draft, then explicitly publish the table. Four new tools bring the catalog from 41 to 45 tools.
- **Independent notebook targets:** each notebook retains its selected environment and captured authentication identity. Concurrent SQL/FetchXML runs, cancellation, queued execution, completions and conversion use the correct notebook context. Outputs, errors, record links, exports and query history retain the executed target.
- **Explicit flow activation:** `ppds flows enable` and `disable` target one flow or a bounded set in a named solution. Preview dependency blockers and a plan hash, acknowledge protected targets, then receive verified per-flow results, including unchanged, partial and uncertain outcomes.
- **More reliable diagnostics:** plugin deployment retains earlier errors when a later operation also fails; diff cancellation reaches all collection stages. Web-resource creation reports missing/mismatched publisher prefixes without silently renaming resources. Form selectors prefer stable IDs and reject ambiguity while preserving unique legacy GUID-name selection.
- **Maintenance beyond these features:** runtime dependencies, Extension development tooling, documentation generation and validation infrastructure have been refreshed. Release validation now includes isolated managed-form roundtrips, native notebook hosts, bounded flow fixtures and stricter test aggregation/cleanup evidence.

### Upgrade and compatibility notes

- Existing CLI form writers now require `--confirm-env <resolved-url>` when effective protection requires acknowledgement. MCP uses `confirmEnvironment`; permission to switch with `--allowed-env` is not permission to write. Read-only sessions reject the covered form/flow writes. These restrictions are deliberate behavior changes for existing scripts.
- MCP captures the startup profile and target; allowed switches affect future calls in that session, without altering global defaults or redirecting work already in flight. Restart the server after creating/replacing startup authentication. `ppds_auth_who` reports the actual session target, including an explicit environment override.
- Update the Extension and bundled daemon together. Missing or mismatched captured identity fails closed with recovery guidance. The new notebook acknowledgement is not DML authorization. Valid legacy notebooks with missing or partial target metadata remain readable.
- Duplicate tab/section labels or names now require an unambiguous selector; use stable IDs. Direct .NET consumers embedding CLI/MCP implementation types must review the [signature changes below](#one-release-compatibility-exception) before upgrading.

### Limits to retain in published notes

- This completes bounded slices of #1015 and #1215, not universal protection for every mutation or general MCP FormXML/layout authoring. Adding new tables/columns/forms or arbitrary layouts is outside the MCP form workflow. Locked managed forms require changes to their source managed properties; adding an unmanaged solution does not bypass the lock.
- Draft fingerprints and flow plan hashes are preflight checks, not atomic compare-and-swap or transactions. Avoid concurrent external editors; inspect completed/unknown phases before retrying an interrupted write. No automatic rollback or blind retry of ambiguous submissions is promised.
- MCP form publication publishes **all pending customizations for that table**, requires `confirmPublishEntity`, and verifies only the selected form afterward.
- Flow activation does not validate connector runtime health or invoke a flow. Disabling does not cancel existing runs. One blocked dependency prevents the batch from starting; failures after execution begins can leave partial results. Flow activation is not automatic during solution import.
- Notebook per-cell environment overrides remain deferred. Cancellation isolation does not establish remote Dataverse cancellation timing.

## One-release compatibility exception

On **2026-11-01**, Josh explicitly approved the version table above and a **one-release exception for CLI 1.5.0 and MCP 1.3.0**. The exception covers the intentional protected-write/session behavior changes and the CLI/MCP implementation-signature incompatibilities listed below. It treats these packages as the documented .NET tools while disclosing the impact on custom embedders.

This decision does **not** declare the release fully backward-compatible, promise binary compatibility for custom embedders, change the general major-version policy, permit future incompatible minor releases, or waive stable-release security/validation gates. No standalone library source API or strong-name identity change is included. The approval authorizes release preparation; tags, publication, deployment and live writes remain separately prohibited until authorized.

### Script and session migration

- Add `--confirm-env <resolved-url>` to existing protected CLI form-write scripts. Resolve/review the actual target; a mismatched acknowledgement fails before writing. Existing read-only restrictions remain effective.
- MCP form callers supply `confirmEnvironment` when required. `--allowed-env` only authorizes switching. Supply the exact table logical name as `confirmPublishEntity` for table-wide publication and inspect partial/unknown phases before retrying.
- Restart MCP after creating/replacing its startup authentication. External default changes no longer redirect a running session. Allowed in-session switches affect subsequent calls, and `ppds_auth_who` reports that session's target.
- Upgrade the Extension with its matching bundled daemon and restart it when instructed. Missing/mismatched captured identity fails closed. Valid legacy notebook target metadata is retained; notebook target acknowledgement is not DML authorization.
- Replace duplicate form labels/names with stable tab/section IDs. Unique legacy GUID-valued names still work when no true ID matches.

### Custom .NET embedding migration

These are public declarations in the CLI/MCP **tool assemblies**, not new features of the standalone Auth/Dataverse/Migration/Query/Plugins libraries. Consumers embedding those tool types must rebuild/adapt; old binaries are not claimed compatible.

| Contract | Change and required adaptation |
| --- | --- |
| `IWebResourceService.CreateAsync` | Return type changes from `Task<Guid>` to `Task<CreateWebResourceResult>`. Read `Id` and handle `Warnings`; update custom implementations. |
| `FormService` constructor | The three-parameter CLR constructor becomes five parameters with optional confirmation/coordinator arguments. Recompile callers and supply a resolved confirmation service for writes; the no-context fallback deliberately rejects mutations. |
| `FormDetail` positional record | Constructor and `Deconstruct` expand from eight to ten values (`DraftHash`, `State`). Rebuild construction/deconstruction consumers and adapt eight-value deconstruction. |
| `IFormService` | Custom implementations must implement `AddFieldDraftAsync` and `PublishFormEntityAsync`. |
| `IDaemonConnectionPoolManager` | Custom implementations must add `GetOrCreateCapturedServiceProviderAsync`. |
| `IMcpConnectionPoolManager` | Custom implementations must add `GetOrCreateCapturedPoolAsync`. |

The original three-argument `DaemonConnectionPoolManager` constructor remains available; its new interactive-auth-policy overload is additive. Added `FlowInfo` and `ConnectionReferenceInfo` properties are additive. None of these details authorizes broad library compatibility exceptions for later releases.

## Component notes

### CLI 1.5.0 — since 1.4.2

**Added:** `flows enable`/`disable` with exact ID/unique-name selection or `--all --solution`, `--dry-run`, optional `--expected-plan-hash`, target acknowledgement, count limit (default 100) and per-flow verification timeout (default 60 seconds). Existing form mutations share the same resolved-context safety guard.

**Fixed:** preserve accumulated plugin deployment errors on subsequent failures and correctly describe secondary-entity-only message filters (#1360); propagate plugin diff cancellation throughout collection/comparison (#1317); expose structured publisher-prefix warnings and correct the literal `<file>` update guidance (#1236); bind query RPCs/history to captured identity/target (#1218); prefer real form element IDs, reject ambiguous names/labels, retain unique legacy GUID-valued names, page complete form listings, and propagate form-operation cancellation accurately.

**Changed:** refresh System.CommandLine 2.0.9 → 2.0.14, Nerdbank.Streams 2.13.16 → 2.14.411 and the shared Microsoft.Extensions 10.0.14 dependency train. Auth/Dataverse dependencies carry JWT 8.23.0. JSON form inspection adds draft hash/state; web-resource creation adds warnings. Protected form-write acknowledgement and captured-profile semantics require the upgrade guidance above.

### MCP 1.3.0 — since 1.2.2

**Added:** `ppds_forms_list`, `ppds_forms_get`, `ppds_forms_add_field`, and `ppds_forms_publish`. Draft editing requires stable IDs and a fresh unpublished draft fingerprint; dry-run is available for adding a field. Results retain write, solution association, publication and verification phases.

**Fixed/changed:** capture startup profile/target, keep environment selection within the session, preserve in-flight targets and avoid pool reuse across captured principals. Auth inspection now agrees with actual operations after `--environment` overrides and session switches. Enforce read-only/acknowledgement for form mutations and separate table-publication acknowledgement. Consume the refreshed CLI/runtime dependencies. The catalog has 45 tools; existing tool names remain available.

### Extension 1.8.0 stable — since 1.6.2

**Added:** notebook toolbar target selection and **Use session default**, plus in-memory acknowledgement for Production/Unknown notebook targets.

**Fixed:** independent notebook/profile identity during overlapping runs, cancellations and queued work; correct target attribution in result links, exports and history; captured context for completion and query transfer/conversion; preservation of valid legacy partial/missing environment metadata.

**Changed:** bundle the matching final CLI release, including flow/form safeguards and reliability fixes. Update development/packaging tooling: `@vscode/vsce` 3.9.2 → 4.1.0, `@vscode/test-electron` 3.0.0 → 3.1.0, ESLint 10.5.0 → 10.13.0, typescript-eslint 8.70.0 → 8.72.1 and Stylelint 17.14.0 → 17.16.0, with corresponding lockfile maintenance. These are development changes; the existing VS Code `^1.116.0` and Node 22 development requirements are retained. Stable releases use an even minor version.

### Library notes — coordinated servicing, no new library API features

- **Auth 1.2.0, since 1.1.2:** update Microsoft.Extensions dependencies to 10.0.14, System.IdentityModel.Tokens.Jwt to 8.23.0, and SourceLink build tooling to 10.0.403. Authentication source/public APIs are unchanged.
- **Dataverse 1.4.0, since 1.3.2:** the same Extensions/JWT/SourceLink servicing updates; connection-pool library source/public APIs are unchanged. Captured session/pool changes belong to the CLI/MCP application layer.
- **Migration 1.3.0, since 1.2.2:** consume the refreshed Dataverse graph, update direct Extensions dependencies to 10.0.14 and SourceLink to 10.0.403. Migration source/public APIs are unchanged.
- **Query 1.1.0, since 1.0.2:** consume the refreshed Dataverse graph and SourceLink 10.0.403. SQL engine source/public APIs are unchanged; notebook/RPC targeting fixes are in the CLI/Extension.
- **Plugins 3.1.0, since 3.0.1:** SourceLink build tooling 10.0.403; attribute/enum source and runtime contract unchanged. Plugin deployment/diff fixes are CLI changes, not new library attribute behavior.

These library minor numbers reflect the approved coordinated-release policy; their dependency/build servicing does not add new library API features.

## Validation and maintenance notes

The completed candidate validation covers managed/unmanaged form roundtrips and locked rejection; 20 core flow CLI calls plus the separately approved unbound-reference blocker test with unchanged flow states/versions; and native Windows VS Code 1.116.0/1.144.0 two-organization notebooks with 12 bounded identity reads. Fixture cleanup and temporary QA recoverable deletion were verified. The purpose-built notebook live host is distinct from the shipped `serve` entrypoint; no broader remote-cancellation claim is made.

Engineering changes include required Python-suite aggregation (#1357), deterministic update-check clocks/completion (#1361), bounded plugin propagation polling and exact-owner cleanup (#1314), managed-form fixture provenance/retained managed-view coverage (#1240), primary-failure preservation, interrupted-process/unknown-outcome retention, and native notebook CI. Additional test dependencies were refreshed (FakeXrmEasy 3.9.6, documentation/TUI test dependency maintenance), and test-only CodeQL/style/disposal findings were corrected. These improve release confidence without adding product commands.

Production dependency checks passed for the validated candidate; development/docs advisories remain disclosed.
